## Key decisions (and why)

- **Menu/context detection is TASK-BASED + fail-safe.** `game_read` (gamestate.c) decides the on-screen context by scanning `gTasks` for each menu's active input-handler task (`task_active`/`find_bag_list_task`), NOT by windowId/callback heuristics. **Why:** heuristics (stale `sMenu.windowId`, stale `gMenuCallback`) repeatedly false-positived and **blocked walking**; a wrong/absent task address now just means "not detected" → the overworld still walks. This is the structural cure for the recurring walk bug.
- **"In battle" = `callback2==BattleMainCB2`, not `gBattleTypeFlags`.** `gBattleTypeFlags` is zeroed at battle *setup*, not end, so it lingered into the field → whole post-battle screen read as a battle dialog (tap=A everywhere).
- **Walk is HYBRID:** quick-tap = BFS route to that tile (doors/ladders/NPCs as terminals; NPCs block transit so it routes *around* them); hold/slide = directional steer (robust at any speed incl. bike). **Why:** the old BFS continuous-retarget desynced on bikes.
- **3D depth = sprite-pop 2.5D on the single composited frame; NO extra emulation pass.** True volumetric/occlusion-correct 3D is a **hardware budget wall** (each separated layer needs a full extra mGBA pass; both cores already saturated). So we overdraw shifted sub-rects (characters via OAM, scenery via Emerald metatile layer-type) per eye. Honest ceiling: convincing 2.5D, faint edge ghosting, Emerald-only scenery.
- **HD-2D:** DoF + LDR bloom are the cheap high-impact wins (fixed-function screen-space). **AI *depth* maps = not worth it** (garbage on 16px pixel art, impossible at runtime, and our analytic `tdepth` is a better *dynamic* signal). **AI *normal* maps = worth it only for sprite/tile lighting** (PICA200 has HW normal-mapping). PICA200 = no fragment shader (only vertex/geometry shader + 6 TEV combiner stages + fixed fragment-lighting + fog LUT).
- **Co-op overworld:** SEE the peer via a **citro2d overlay avatar** (not RAM object-injection — that needs sprite+palette+callback and we only have `write8/16`, no `write32`/ROM-call). INTERACT via the games' **own Union Room/link** (a trade/battle is a link state-machine; it **cannot** be force-started by RAM pokes — that crashes).
- **Reliability-first for touch:** one feature at a time, hardware-verified, with an on-device debug readout. The proven-robust pattern is **write the game's cursor variable + pulse A** (battle action/move/party/target/field-menu all use it).
- **Wireless link = a custom `GBASIODriver` net peer over UDS, NOT a fork of mGBA's lockstep.** One 16-bit SIO word per "round", round-locked + exactly-once; the HOST is MULTI master (seat 0), the JOIN the slave. The byte transport (`netlink.c`) is **proven perfect** (toN=0, byte-identical) — every remaining failure was pacing/word-timing, not loss.
- **The slave must be PACED to the host's emulated rate (state D), and its SIO word captured LAST.** Frozen/over-paced → can't run its main-loop link code in time → sends **stale words** → master CHECKSUM error (desync, not loss). Free-run → clock outruns master → divergence. And Gen-3 writes `SIOMLT_SEND` in the main loop *after* the serial ISR, so capturing/pre-sending the word early ships a stale value (the reverted `f140f08`). **Capture at the proven post-ISR edge; never pre-send.**
- **SPEED is radio-bound, proven by instrumentation — do NOT optimize our worker loop.** rtt~24 ms but pure-ping~5 ms and our turnaround~2 ms → the ~19 ms is the UDS round-trip, which is variable (5–25 ms) + lossy. Levers are the wifi channel and/or a different transport (UDP), measured by `3DGBA-netbench`. (Verify libctru internals in source: `udsGenerateDefaultNetworkStruct` DOES memset → channel defaults to 0/auto; an agent claimed otherwise and was wrong.)
- **The trade failure is `RECEIVED_NOTHING`, NOT checksum/LAG (corrected 2026-06-28).** The red error at the attendant is `gRemoteLinkPlayersNotReceived → CB2_LinkError` (link.c ~597-615): the game keeps reading idle/"nothing" from the peer, the connection forms then times out — with **no `gLinkStatus & 0x7F000` bit set** (so NOT checksum, NOT LAG_SLAVE, NOT queue-full). The relay hands the game all-zero/idle commands whenever the peer's real words aren't there in time (racing ahead / clock divergence / radio loss). **Two prior diagnoses were wrong:** (a) framing everything as 8-word commands (the handshake is **single-word** `B9A0`/`8FFF` → it never crossed → hung); (b) blaming LAG_SLAVE (the slave watchdog never fired). **Rule: read the game's own `gs`-log first; the raw `net`-log is easy to over-read into a false story.**
- **The fundamental fix = LOCAL TERMINATION (Celio model), not transport tuning.** 3DGBA today relays one 16-bit SIO word per UDS round-trip → latency-bound. Celio-Link (open-source, GPL-3.0) terminates the GBA link protocol **locally** — the driver *is* the link partner, answers every SIO word itself at full speed, and ships only **semantic 8-word commands** over the wire. The game never waits on the radio. **Why this over channel/UDP tuning:** even a perfect channel only buys a constant factor; local termination removes the per-word round-trip entirely (full-speed) *and* fixes RECEIVED_NOTHING (the game is never fed mid-stream idle). The exact wire format needed to build it is captured in the `learn` skill (`references/gen3-link-protocol.md`). **Credit Celio in NOTICE/README when this lands** (the user asked; all licenses — Celio GPL-3.0, mGBA MPL-2.0, 3DGBA GPLv3 — are compatible).

## Gotchas / constraints

- **Edit `main.c`/`touch.c` via Python scripts** with exact `\t`/`\n` strings + `.count()` asserts — the files are tab-indented and the Edit tool fails on whitespace mismatches. (A linter sometimes reformats between reads.)
- **3 usable ARM11 lanes only:** core 0 = main thread + worker A; core 2 = worker B (needs `CanAccessCore2`); core 1 = audio thread (syscore slice via `APT_SetAppCpuTimeLimit`). **Core 3 is OS-reserved.** No budget for a second emulation pass.
- **mGBA is MPL-2.0** (file-level copyleft) — don't modify mGBA files; the wireless plan adds a **network `GBASIODriver` as a peer driver**, not a fork.
- **All RAM addresses verified vs the pret byte-matched sym maps.** **LeafGreen (`BPGE`) ROM addresses are FireRed-derived (unverified)** → those features may be inert on LG (fail-safe). 3D scenery (M4) is **Emerald-only** (`mapHeader` is 0 elsewhere → falls back to sprite-pop).
- `gbacore` exposes only `read8/16/32` + `write8/16` — **no `write32`, no ROM-call/trampoline.** This is why co-op uses an overlay (not object injection) and interactions ride the real link.
- Reads of a worker's core must happen at the **parked per-frame handshake** (where `game_read`/the depth+OAM snapshot already run), never during a link free-run. (The link-error gs reads ride the same parked window.)
- **Wireless = state D + edge-strict, BOTH consoles, FROM THE START.** Mid-trade toggling between pacing states carries forward accumulated desync (the round-lock is safe, but the game's checksum/queue state isn't) — pick the state before the trade. The netlog `# rate`/`# ping`/`turnus`/`exp`/`force` columns + the link-error decode `(gLinkStatus & 0x7F000)>>12` (HW/CHECKSUM/QUEUE_FULL/LAG_MASTER/INVALID_ID/LAG_SLAVE) are the diagnostic surface; logs → `sdmc:/cias/netlogs/`.
- **A frozen guest's emulated frame counter stops** → log liveness off a WALL-CLOCK heartbeat (`svcGetSystemTick`), not emulated frames, or you go blind exactly when it hangs.
