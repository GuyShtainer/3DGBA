**Evidence conventions.** Every load-bearing fact is tagged:
- **[V]** verified on THIS machine today (file read, command run, symbol dumped — cite inline).
- **[I]** inferred (usually from Citra lineage, Azahar being its successor) — MUST be verified
  in the implementing slice before any test depends on it; BUILDLOG records the verification.
- **[M]** measured-in-slice: a number deliberately left open (boot time, tap timing) that the
  slice measures once and freezes into a constant with a comment.

Key app-side facts the whole design leans on (all [V] from today's source/binary reads):

- **Symbols: file-scope statics ARE in the ELF symtab.** `arm-none-eabi-nm 3DGBA.elf` (4456
  symbols) shows e.g. `004d1884 b g_renderSeq`, `0049b460 d g_appActive`, `004d1869 b g_quit`,
  `004d320d b s_ctlOn`. The repo `.gitignore` ignores `*.map` and `*.lst`, and `3DGBA.map` is
  absent right now — so **nm on `3DGBA.elf` is the primary symbol source**, the `.map` a
  cross-check when present. Both are regenerated by
  `export DEVKITPRO=/opt/devkitpro DEVKITARM=$DEVKITPRO/devkitARM && make -j8`.
- **`g_renderSeq`** (main.c:91, incremented once per render-loop frame at main.c:2584) is a
  monotonic ~60 Hz liveness counter readable over GDB. **`g_appActive`** (main.c:85) is true
  while not HOME/sleep-suspended. **`g_quit`** (main.c:74).
- **The D4 control channel** arms iff `sdmc:/cias/control` exists at session start
  (main.c:2521, one `stat`), reads `sdmc:/cias/control/move_p{1,2}.txt` (main.c:302), and
  **consumes scripts on pickup via `remove()`** (main.c:460 — "a stale script can never
  re-fire"): file disappearance is a filesystem-observable ACK. Status lines append to
  `sdmc:/cias/netlogs/3DGBA_control_<MMDD>_<HHMMSS>.txt`, `fflush` per line, first line
  `"# control p1=<code> p2=<code> dir=sdmc:/cias/control ..."` (main.c:270–285, 2522–2531).
- **The gs log dumps on Quit/Change-games** (`gs_dump(-1)`, main.c:4147) and on link error
  (main.c:3162/3412) to `sdmc:/cias/netlogs/3DGBA_gs_*.txt`. **The D3 CSV writes ONLY during
  an armed wireless session** (diag.h:312–313: `s_csvFile && wlOn`) — smoke must NOT expect a
  CSV from a solo boot.
- **ROM locations:** the current build's `ROM_DIR` is **`sdmc:/3DGBA`** (rompicker.h:13) and
  `RECENT_PATH` is `sdmc:/3DGBA/recent.bin` (rompicker.c:104). The user's REAL ROMs+saves
  live in the *old* folder **`sdmc/dual-gba/`** (`gameA.gba`, `gameA.sav`, `gameB.*`,
  probed today); `sdmc/3DGBA/` currently holds only `settings.bin`. Consequence: fixture
  copies placed in `sdmc/3DGBA/` are **harness-created files** — the clean fixtures-vs-user-
  data split of §H4 falls out of the app's own rename.
- **qt-config.ini** is Qt-escaped INI (`[Data%20Storage]` observed). Probed keys/sections:
  `[Layout] layout_option=0` (line 270), `[Miscellaneous] check_for_update_on_start=true`
  (306), `[System] init_clock=0` / `init_time=946681277` / `init_time_offset=0` (370–379),
  `[UI] Paths\screenshotPath=` (464), `UILayout\geometry*=@ByteArray(...)` (621–622),
  `fullscreen=false` (637). Every key has a sibling `key\default=true` flag that MUST be set
  to `false` when the harness pins a value, or Azahar may treat the value as unset [I —
  standard Citra-family settings behavior; verify by diffing the file after Azahar rewrites it].

## H1 — File layout + lifecycle

**H1.1 Layout.** Everything committed lives in `tools/emutest/`; the skill in
`.claude/skills/emutest/`; docs in `docs/phase16-emutest/`. No other paths are touched
(PHASE inv. 1/6).

```
tools/emutest/
  setup.sh          # venv build + host tests + smoke gate (H1.3)
  azctl.py          # launch/stop/status/restore — profile state machine (H1.5)
  gdbio.py          # GDB RSP client + symbol table (nm/map) + verify-base
  ctm.py            # CTM synthesizer/inspector (tests-as-data JSON -> .ctm)
  see.py            # window lookup + screencapture + screen crops (SKIP-aware)
  compare.py        # ref-vs-new heat-map diff, --tolerance/--max-diff, exit code = verdict
  zoom.py           # nearest-neighbour zoom crops (5x7-glyph readability)
  sheet.py          # captioned contact sheets, dual-screen geometry
  smoke.sh          # the end-to-end gate; per-channel PASS/FAIL/SKIP table (H3)
  emutest.mapsyms   # (generated, gitignored) cached symbol table with source mtime stamp
  tests/            # host-pure tests + tiny fixtures (H6)
  runs/             # (gitignored) per-run artifact dirs, H2.8
  state/            # (gitignored) pid file, profile backup, last-run pointer (H1.5)
  .venv/            # (gitignored) built by setup.sh
```

`compare.py`/`zoom.py`/`sheet.py` are ports of the PokeDNA scratchpad tools (platform-
agnostic per the report §Deliverables); `sheet.py` learns the two-screen layout constants
from §H2.6. All Python is stdlib + the two wheels of H1.2; every file starts with a header
comment citing its design source (PokeDNA report / Azahar source file) — house rule.

**H1.2 setup.sh installs** into `tools/emutest/.venv` (created with `/usr/bin/python3 -m venv`,
falling back to Homebrew python3 if the system one lacks venv/pip):
- `pillow` — PNG encode/crop/diff/zoom for see/compare/zoom/sheet.
- `pyobjc-framework-Quartz` — `CGWindowListCopyWindowInfo` for window-id + bounds lookup
  (see.py). Only imported inside see.py so every other tool runs without it.
- **NO numpy.** Justification recorded here per the task brief: the pixel metrics we need
  (dark-fraction, mean luma, per-pixel abs-diff count) are exact with `PIL.ImageChops.difference`
  + `Image.histogram()` on images ≤400×480; the PokeDNA harness used numpy only because
  libmgba-py hands over a raw C buffer, which does not exist here. If a future slice needs
  SSIM-class metrics it adds numpy WITH a BUILDLOG justification.
- Prints (does not run) the optional `brew install cliclick` note for the Accessibility-gated
  channel; cliclick absence is a SKIP, never a failure.

**H1.3 setup.sh gates itself** (PHASE inv. 7, the PokeDNA setup.sh pattern), in order:
1. venv build + pip install (pinned versions, `--require-virtualenv`);
2. `tests/run_host_tests.sh` — all host-pure tests (H6) must pass;
3. `smoke.sh` — the live gate. `setup.sh --no-live` stops after (2) for CI-ish contexts, but
   the default is the full gate and the skill tells sessions to run the default.
setup.sh is idempotent: re-running rebuilds the venv only when `pip freeze` mismatches the
pinned list; steps 2–3 always run.

**H1.4 .gitignore addition** (one hunk appended to the repo `.gitignore`, the only file
outside the three harness dirs this phase may touch pre-HANDOFF):

```
# phase-16 emulator harness — machine-local state, never source
tools/emutest/.venv/
tools/emutest/runs/
tools/emutest/state/
tools/emutest/emutest.mapsyms
```

**H1.5 azctl profile + instance state machine.** All mutable state under `tools/emutest/state/`:
`azahar.pid` (PID + spawn time of the instance WE started), `qt-config.ini.bak` (the user's
config, byte-exact copy), `last_run` (path of the newest run dir).

States: **CLEAN** (no `qt-config.ini.bak` on disk — user profile active) and **APPLIED**
(backup exists — harness profile active). Transitions:

- `boot`:
  1. **Crash recovery FIRST**: if `qt-config.ini.bak` exists, the previous run died before
     restore → restore it over `AZ_CFG` NOW (before anything else), log
     `recovered stale profile backup` to the new run dir, delete the stale `azahar.pid`.
  2. **Single-instance**: if `azahar.pid` names a live process we spawned → SIGTERM, wait 5 s,
     `kill -9` survivors (a modal dialog swallowed SIGTERM once — probed fact). If an azahar
     process exists that we did NOT spawn → **abort with a message** ("close Azahar or re-run
     with --force"); `--force` extends the kill to untracked instances. Rationale: PHASE inv. 2
     — the user's own emulator session is user data too.
  3. Backup: copy `AZ_CFG` → `qt-config.ini.bak` (now in APPLIED).
  4. Apply the harness profile (H1.6) via an in-place INI edit that preserves every untouched
     key (Qt escapes intact — the editor is host-tested, H6.3).
  5. Spawn `AZ_BIN -w [flags] $APP` detached, stdout/stderr → run dir; write `azahar.pid`.
     (Session note, for the skill not the code: Bash-spawning the GUI has needed
     `dangerouslyDisableSandbox: true` — a sandboxed launch may fail silently.)
  6. Readiness wait (H3.2), then print the run dir and status line.
- `stop`: SIGTERM tracked PID → wait 5 s → `kill -9`; harvest `AZ_LOG` (+ `.old`) and any NEW
  files under `AZ_SD/cias/netlogs/` into the run dir; restore `qt-config.ini.bak` → `AZ_CFG`
  and delete the backup (→ CLEAN); delete `azahar.pid`. Every step tolerant of
  already-done (idempotent).
- `restore`: just steps restore+delete-backup — the manual escape hatch; no-op in CLEAN.
- `status`: reports process (ours / foreign / none), profile state, gdb port reachability,
  `last_run`.

**H1.6 The harness profile** (PHASE inv. 3 "deterministic profile") — exact key edits, each
with its probed line number in today's `AZ_CFG`:

| Section/key | Harness value | Why / source |
|---|---|---|
| `[Layout] layout_option` | `0` (+`\default=false`) | top-over-bottom default layout → static touch/crop math [V line 270, already 0] |
| `[Miscellaneous] check_for_update_on_start` | `false` | the update dialog hijacked a run and swallowed SIGTERM [V line 306] |
| `[System] init_clock` | `1` | fixed-time RTC → reproducible screenshots (PokeDNA RTC-pinning lesson) [I: 0=system/1=fixed is Citra settings semantics — verify in slice via the settings UI] |
| `[System] init_time` | `946681277` (keep the probed default value, but pin `\default=false`) | any fixed value works; keeping the existing one minimizes drift [V line 376] |
| `[UI] fullscreen` | `false` | windowed, deterministic geometry [V line 637] |
| `[UI] Paths\screenshotPath` | `<run dir>/azshots` | if Azahar's built-in screenshot is ever driven, output lands in the run dir [V line 464] |

Window geometry: `UILayout\geometryRenderWindow` is an opaque `@ByteArray` blob [V line 622].
**Decision: do NOT forge the blob.** see.py measures the actual window rect per shot via
Quartz and parameterizes the crop math with it (H2.6) — resolution-independent and blob-free.
(Open Question 5 keeps the pin-the-blob option if measurement proves flaky.)

## H2 — Session UX

Design target: a Claude session types short commands, every one idempotent, every one exits
0 = pass / 1 = fail / **75 = SKIP** (sysexits EX_TEMPFAIL; smoke.sh maps 75 → the SKIP column).
All commands are `tools/emutest/<tool>.py` run through the venv shim `tools/emutest/run`
(a 3-line sh wrapper: `exec "$(dirname "$0")/.venv/bin/python" "$(dirname "$0")/$1.py" ...`),
so the documented spelling is e.g. `tools/emutest/run azctl boot --gdb`.

**H2.1 azctl**
```
azctl boot [--gdb[=PORT]] [--movie F.ctm] [--record F.ctm] [--fresh-sd-fixtures]
           [--wipe-netlogs] [--force]
azctl stop | status | restore
```
- `--gdb` adds `-g PORT` (default harness port **24689** — Citra's traditional gdbstub port
  [I]; we always pass it explicitly so the default never matters).
- `--movie` / `--record` map to `-p` / `-r` (probed CLI).
- `--fresh-sd-fixtures` / `--wipe-netlogs`: §H4.
- `boot` while already booted (ours) = restart (stop→boot); `stop` while stopped = success.

**H2.2 gdbio**
```
gdbio verify-base
gdbio read  <symbol|0xADDR> <len>          # hex+ASCII dump to stdout, raw to --out F.bin
gdbio read-u32 <symbol|0xADDR>             # LE u32, prints decimal + hex
gdbio poll  <symbol> [--changed | --expect V] [--timeout S] [--interval MS]
gdbio syms  [--refresh]                    # (re)build emutest.mapsyms from nm/.map
```
- Symbol table: `arm-none-eabi-nm 3DGBA.elf` primary (statics included — [V] above), `.map`
  cross-check when present; cache invalidated on `3DGBA.elf` mtime change. Missing ELF →
  hard error telling the operator the `make` line.
- `poll --changed` samples twice (or until timeout) and passes iff the value differs —
  the liveness primitive (H3.4).
- Transport: pure-python RSP over TCP (`$...#nn` checksummed packets, `m addr,len` reads)
  [I: Azahar's stub is Citra's `src/core/gdbstub/gdbstub.cpp` lineage — packet dialect
  verified in slice against a live connect; `arm-none-eabi-gdb` at
  `/opt/devkitpro/devkitARM/bin/` is the fallback client for interactive debugging only].
- If attaching halts emulation [I — Open Question 3], gdbio must resume (`vCont;c` or detach)
  after every read so reads are observation, not interference.

**H2.3 ctm — tests as data** (the PokeDNA JSON-script rule):
```
ctm make script.json out.ctm
ctm inspect f.ctm
```
`script.json` is a timeline list, times in frames @60:
`[["wait",120], ["tap","START"], ["hold","A",30], ["touch",160,120,10], ["release"]]`
— taps default to hold 8 / release 8 frames (the PokeDNA edge-latch rule). `ctm make` is
deterministic (same JSON → same bytes; golden-tested, H6.2). Byte format pinned from
Azahar's open source (`src/core/movie.cpp` / `movie.h` [I: Citra-lineage magic `CTM\x1B` —
the slice MUST verify by recording a real movie with `-r` while pressing a known input, then
hex-diffing against the synthesizer; that recording becomes the golden fixture]).
`ctm inspect` decodes a movie back to the timeline — the round-trip is the format proof.

**H2.4 see**
```
see shot top|bottom|both out.png [--raw-window out_full.png]
```
Quartz window lookup (owner name `azahar` [V process name]) → `screencapture -l<windowid>` →
crop per H2.6. **Permission gate:** if Screen Recording is missing (detected: the capture
contains no window content / CGWindowList returns no title for foreign windows), print the
grant instructions (System Settings → Privacy & Security → Screen Recording → enable the
host app (Visual Studio Code), restart it) and **exit 75**. Never fail, never silently pass
(PHASE inv. 4; grant currently pending on this machine — probed).

**H2.5 compare / zoom / sheet** keep the PokeDNA CLIs:
`compare ref.png new.png [--tolerance N] [--max-diff N] [--heatmap out.png]` (exit code =
verdict); `zoom in.png out.png --rect x,y,w,h --scale 4..8`; `sheet out.html img:caption...`
(HTML with inlined images — raw attachments don't render, report rule).

**H2.6 Screen-crop math** (used by see.py, sheet.py, and any future touch→pixel mapping).
With `layout_option=0` and measured window content size `W×H`: scale `k = H/480`; top screen
rect `((W−400k)/2, 0, 400k, 240k)`; bottom `((W−320k)/2, 240k, 320k, 240k)` [I: the Citra
default layout stacks 400×240 over 320×240 in a 480-line frame — the formula is host-tested
(H6.4) and slice-verified once against a real screenshot with a visible screen border].
macOS Retina: `screencapture` returns 2× pixels — see.py normalizes by the ratio of image
size to window bounds before cropping.

**H2.7 smoke.sh** — no arguments needed; `--no-live` (host channels only) and `--rom` (arm
the Tier-B loop, §H3.6) are the only flags. Output ends with the table:

```
CHANNEL    VERDICT  DETAIL
run        PASS     boot 8.2s, pid 4711
read-state PASS     verify-base 3/3 anchors; renderSeq 60Hz
press-ctm  PASS     START at picker -> observed effect (H3.5)
press-d4   PASS     move_p1.txt consumed 1.3s; control log header ok   (SKIP unless --rom)
sdmc       PASS     gs log appeared on quit; header parsed
see        SKIP     Screen Recording not granted -> grant + restart VS Code
```
Exit code: 1 if any FAIL; 0 otherwise (SKIPs do not fail the gate but are always printed —
the phase-13 verdict.sh rule).

**H2.8 Per-run dirs.** Every `azctl boot` creates `tools/emutest/runs/<UTC yyyymmdd-HHMMSS>/`
holding: `cmdline.txt`, azahar stdout/err, the applied profile diff, harvested `azahar_log.txt`
(+`.old`), every NEW `sdmc/cias/netlogs/` file (copied on `stop`), all screenshots/movies/
polls the other tools produce (they default their outputs into `state/last_run`'s dir), and
`events.log` — one line per harness action. A run dir is append-only evidence; nothing in it
is ever needed for the next run to work.

## H3 — The zero-permission closed loop (smoke's spine)

Two tiers. Tier A needs nothing but the repo + Azahar; Tier B additionally uses ROM fixture
copies (H4.2) and is the loop that exercises the app's own D4 input channel end-to-end.

**H3.1 S1 preflight (host):** `AZ_BIN` exists and `--version`/Info.plist says 2125.1.2 (warn,
don't fail, on other versions — but record it; never update mid-investigation, H5); `APP` and
`3DGBA.elf` exist (else print the `make` line and FAIL); symbol cache builds; venv imports ok.

**H3.2 S2 boot:** `azctl boot --gdb=24689`. Readiness = the gdb TCP port accepts a connection
AND `AZ_LOG` has rotated (new file mtime > spawn time). Timeout: **BOOT_TIMEOUT, default 30 s
until measured [M]** — the slice measures cold boot-to-picker (no ROMs in `sdmc:/3DGBA` →
the app sits at the game-select screen) and freezes the constant + measured value in BUILDLOG.

**H3.3 S3 verify-base** (`gdbio verify-base`): read 64 bytes at **three** symbols spanning
sections — one `.text` (e.g. `ctl_log_line`, nm `t 001eb328`), one `.rodata`, one initialized
`.data` (`g_appActive`, nm `d 0049b460`) — and byte-compare each against the SAME vaddr's
bytes extracted from `3DGBA.elf`'s program headers (stdlib ELF parse — no pyelftools; ~60
lines, host-tested H6.5). This needs **no known compile-time constant**: the ELF file is the
constant. Pass = 3/3 match ⇒ the .3dsx runs at link-time addresses with no slide [I: expected
for 3dsx under Azahar; if it EVER mismatches, verify-base FAILS loudly and Open Question 2's
slide-discovery fallback activates — do not guess]. `.bss` symbols are excluded (no file image).

**H3.4 S4 real-global reads:** `gdbio read-u32 g_renderSeq` twice ≥500 ms apart → strictly
increasing (render loop alive; main.c:2584); `g_appActive == 1`; `g_quit == 0` (main.c:74/85).
Timeout 5 s per read. These three symbols + line cites live in a table INSIDE gdbio.py's
header comment (house rule: cite every address's source).

**H3.5 S5 PRESS via CTM (Tier A):** `ctm make` a movie: wait ~BOOT-equivalent frames, then
tap START. At the ROM-less game-select screen START exits the picker (rompicker.c:153/207
returns −1/false) → expected observable: the app quits — `g_quit` flips to 1 and/or the
process exits within 10 s of the tap [I — **the slice pins which observable is reliable**:
poll `g_quit --changed` while also watching the PID; either transition = PASS. If START at
the picker turns out not to quit, the fallback candidate is a picker-adjacent static chosen
from nm after grepping rompicker.c — main.c's `menuOpen` is function-local (main.c:2422) and
deliberately NOT usable]. This closes RUN→PRESS→READ-STATE with zero permissions.
Note: movie playback starts at app boot (CTM is a from-boot input recording [I: Citra movie
semantics]), so the script's leading wait must cover boot-to-picker — use the [M] constant.

**H3.6 S6 PRESS via D4 (Tier B, `smoke.sh --rom`):** with fixtures staged (H4.2) and
`sdmc/cias/control/` created, pre-drop `move_p1.txt` containing a trivial script (a bare
button tap or `W60` — grammar per control.h; the file may sit there before boot because
pickup is consume-on-read, main.c:460). Boot with a CTM that drives the picker to launch the
fixture pair (or seeds `sdmc:/3DGBA/recent.bin` and answers the resume prompt — slice picks
the shorter reliable path). Pass criteria, all zero-permission:
1. `move_p1.txt` disappears within 10 s of game start (consumed-on-pickup ACK);
2. a new `sdmc/cias/netlogs/3DGBA_control_*.txt` exists whose first line matches
   `# control p1=<4-char code> p2=` (main.c:2527) and which contains a pickup status line;
3. `gdbio read-u32 s_ctlOn == 1` (main.c:2521);
4. after `azctl stop`-driven quit — or a CTM-driven Quit — a new `3DGBA_gs_*.txt` appears
   (gs_dump on quit, main.c:4147): the sdmc read-side check of H4.4.
Timeouts: game-visible within 20 s of picker input [M]; pickup poll every 500 ms.

**H3.7** Smoke NEVER depends on: pixels (see is its own SKIP-able channel), the D3 CSV
(wireless-only, diag.h:313), wall-clock screen content (RTC pinned anyway), or OS input
(Accessibility denied on this machine today — [V] osascript −1743).

## H4 — SDMC bridge rules

**H4.1 User data is untouchable.** `AZ_SD/dual-gba/**` (real ROMs, real `gameA.sav` — [V]
probed) is READ + COPY-OUT only: the harness never writes, renames, or deletes there, ever.
Same for `Nintendo 3DS/`, `3ds/` (dspfirm lives there) and any file the harness did not
itself create (PHASE inv. 2). Enforced in code: a single `sd_guard.assert_writable(path)`
helper that every write in azctl/see/smoke goes through, allowing only the H4.2 allowlist.

**H4.2 Harness-writable allowlist** on the virtual SD:
- `AZ_SD/cias/control/` — created if absent (the app's own opt-in rule, main.c:2521);
  harness-written `move_p*.txt` / `go_p*.txt` / `replay_*` files only.
- `AZ_SD/cias/netlogs/` — app-written; harness may READ always and DELETE only under
  `--wipe-netlogs` (H4.3).
- `AZ_SD/3DGBA/` — the current build's ROM_DIR [V rompicker.h:13]. `--fresh-sd-fixtures`
  copies `dual-gba/gameA.gba`+`gameA.sav` (and B) here as fixtures, records a manifest
  (`state/fixtures.json`: paths + SHA-256 + source mtime), and may later delete/re-copy ONLY
  files listed in that manifest. In-game saving during a harness run writes the FIXTURE save —
  the user's `dual-gba/` originals stay byte-identical (verified post-run by re-hashing the
  originals; a mismatch is a harness bug and FAILS the run loudly). ROMs/saves are already
  gitignored repo-wide (`*.gba`, `*.sav`) and fixtures live outside the repo anyway.

**H4.3 Netlog lifecycle** mirrors the established hardware workflow (wipe before, archive
after): `azctl boot --wipe-netlogs` empties `AZ_SD/cias/netlogs/` (only with the explicit
flag); `azctl stop` always copies every file newer than boot time into the run dir. Default
is NO wipe — stale logs are the user's data until they say otherwise.

**H4.4 What smoke reads from the phase-13 artifacts** (the "state check" leg): the control
log header + pickup lines (H3.6.2) and the quit-time gs log (H3.6.4) — both unconditional
app behaviors. The D3 CSV and wl net logs are DOCUMENTED as wireless-session-only (diag.h:
312–313) so no future slice "fixes" smoke by expecting them; a two-instance UDS experiment
(PHASE inv. 5: experiment, never evidence) is the only context where smoke-adjacent tooling
may parse the CSV, and it reuses `tools/verdict.sh`-style greps rather than new parsers.

emulator from the session: boot/stop with a managed profile, read app globals over GDB,
press buttons via synthesized CTM movies or the app's own sdmc control files, screenshot and
diff screens. Use whenever a 3DGBA change needs a live check without the user's hardware."*

Sections, in order:
1. **Quickstart** — the six commands of H2 with one-line examples; the `tools/emutest/run`
   shim spelling; "always `azctl stop` when done" (profile restore).
2. **The closed loop** — H3's Tier A/Tier B recipes as copy-paste blocks; where run dirs land.
3. **Honest limits** (CLAUDE.md #6 verbatim rule): Azahar cannot prove core-2 contention,
   the 804 MHz budget, L2 effects, UDS latency, stereo fusion, audio/frame pacing. This
   harness makes ITERATION self-serve; **real New-3DS hardware remains the sign-off gate**
   for anything timing-sensitive. Two-instance Azahar + a local room MAY carry UDS code —
   strictly an experiment, never evidence (PHASE inv. 5).
4. **Permission SKIPs** — see/cliclick channels SKIP with exit 75 until the user grants
   Screen Recording (+ Accessibility for cliclick) to the host app in System Settings →
   Privacy & Security, then restarts it; a SKIP is never a pass; the zero-permission loop is
   always available. Session note: GUI launches from Bash may need
   `dangerouslyDisableSandbox: true`.
5. **Pinned emulator version** — the harness profile sets `check_for_update_on_start=false`;
   **never update Azahar mid-investigation** (results stop being comparable and CTM/gdb
   surfaces may shift); each run dir records the version; if Azahar was updated deliberately,
   re-run `setup.sh` (which re-runs smoke) before trusting anything.
6. **User data rules** — H4.1/H4.2 in three bullets: never touch `dual-gba/`, fixtures live
   in `sdmc/3DGBA/` via `--fresh-sd-fixtures`, netlogs wiped only with `--wipe-netlogs`.
7. **The sdmc bridge cheat-sheet** — control-file grammar pointer (control.h), where the
   ack/status lines land, which logs exist when (gs on quit; CSV wireless-only).
8. **Troubleshooting** — stale profile backup = crash recovery on next boot; foreign azahar
   → `--force`; missing `.elf` → the make line; modal dialogs → `kill -9` policy.

**H5.1** The skill is docs-only: it never duplicates constants from the code (addresses, the
[M] timeouts) — it points at the tools, which are self-describing (`--help` on each).

## H6 — Test plan

**H6.1 Split.** Host-testable pure logic runs on every `setup.sh` and in any future slice
gate; live-only behavior is exercised solely by `smoke.sh`. Host tests live in
**`tools/emutest/tests/`** (NOT `test/host/` — that directory is for app code; PHASE inv. 6
keeps this phase out of it). Runner: `tools/emutest/tests/run_host_tests.sh`, which execs
`.venv/bin/python -m unittest discover -s tools/emutest/tests -p 'test_*.py' -v` (stdlib
unittest — no pytest dependency). That run line is printed at the top of every test file.

**H6.2 Host-pure inventory:**
| Test | Pins |
|---|---|
| `test_ctm_golden.py` | `ctm make` bytes vs a checked-in golden `.ctm` recorded from Azahar `-r` in the slice (H2.3); round-trip `make`→`inspect`→same timeline |
| `test_mapsyms.py` | nm-output and `.map` parsing on a checked-in 30-line fixture snippet (addresses, `b/d/t` types, statics) |
| `test_layout.py` | H2.6 crop math at 1×/1.5×/2× window scales + Retina normalization, exact-pixel expectations |
| `test_compare.py`, `test_zoom.py` | image ops on generated-in-test PIL fixtures (no binary fixtures needed); exit-code verdict behavior incl. `--tolerance` boundaries |
| `test_profile.py` | qt-config editor round-trip: value+`\default=false` set, `%20` section names preserved, untouched keys byte-identical, backup/restore/crash-recovery state machine (pure functions on temp dirs) |
| `test_elf_extract.py` | H3.3's stdlib ELF vaddr→file-bytes extraction against a tiny checked-in ELF fixture (built once from a 5-line .c in the slice) |
| `test_ctlscript.py` | the `move_p1.txt` bodies smoke drops are valid per control.h's grammar (string-level checks only — the app's own parser is tested in `test/host/test_control.c`, not re-tested here) |

**H6.3 Live-only** (smoke's exclusive territory): boot/readiness timing, gdb dialect + halt
behavior, verify-base against the running process, CTM playback semantics, D4 pickup, log
harvesting, screenshot capture. None of these get "mock" host tests — a mock would test the
mock (PokeDNA rule: verification against the real thing or not at all).

**H6.4 The gate rule (binding on future slices):** `smoke.sh` is THE gate. Every future
phase-16 slice — and any later phase that touches the harness — reruns `setup.sh` (host
tests + smoke) before its BUILDLOG entry, and the entry records the smoke table verbatim.
A slice that adds a channel adds a row to the table in the same slice. Green host tests
without a smoke run are not a pass (PHASE inv. 4).

**H6.5 Adversarial verification carry-over** (report §Rules): any claimed on-screen defect
found via this harness ships with one captioned image per claim (sheet.py) and repro steps
that a second agent can replay from the run dir alone.

## Open Questions

1. **[M] Boot-to-picker time** — measure cold and warm on this machine; freeze BOOT_TIMEOUT
   and the CTM leading-wait constant from it (H3.2/H3.5).
2. **3dsx load base / slide** — verify-base is expected to prove "no slide" (H3.3). If it
   fails: does Azahar's stub answer `qOffsets`? Decide the discovery strategy only if the
   problem is real.
3. **Does GDB attach halt emulation?** If yes, gdbio must auto-resume after every read; if it
   also pauses the CTM timeline, smoke S5 must connect only AFTER the movie's input lands.
4. **START-at-picker observable** — process exit vs `g_quit` flip vs neither (H3.5); pin one,
   record in BUILDLOG, adjust smoke's press-ctm row detail text.
5. **Window geometry pinning** — measured-rect crops (chosen) vs forging the Qt
   `geometryRenderWindow` blob; revisit only if per-run window placement makes measurement
   flaky (e.g. off-screen spawn).
6. **CTM header semantics** — does the movie file embed its own `init_time`/seed that
   overrides the profile's `[System]` pins during playback (Citra lineage suggests movies
   carry clock state [I])? Determines whether §H1.6's RTC pin also governs movie runs.
7. **`--dump-video` revival** — strict libavutil major-version check fails against Homebrew's
   avutil.60 (probed). Optional channel; only worth a slice if screenshot-based SEE proves
   insufficient for motion bugs.
8. **Richer smoke state via a debug-read page** — if smoke ever needs app state that only
   lives in function-locals (e.g. `menuOpen`), the fix is an app-side exported debug global,
   which is an APP change: record as a BUILDLOG follow-up for a later phase (PHASE inv. 6),
   never a harness workaround that guesses stack addresses.
9. **Two-instance Azahar for UDS experiments** — needs a second data dir (`AZ_DATA`
   override?); out of smoke's scope, experiment-only per PHASE inv. 5; spec'd when attempted.
